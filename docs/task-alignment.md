# 本轮任务核对（C5首包）

回答“有来源支持”与“完成当前任务”是两回事。比如文档同时写了测试和生产规则，回答测试规则可能有原文，但用户要求的是生产范围。已有来源审核继续负责断言支持；本功能另外检查回答是否答偏目标/对象/范围。

## 操作与调用

在任一轮“查看详情”中展开“本轮任务核对”，点击“核对本轮任务（额外模型调用）”。使用现有配置的审核模型，最多一次请求、禁SDK隐式重试。打开详情和普通发问不会自动额外审核，不会重跑检索或改写旧答案。

核对保存在原轮次 `resolution.task_alignment_checks`，刷新恢复。相同输入/协议已有有效结果会复用，不能靠重复点击刷分。不可用结果可显式另发请求，旧失败保留。正在运行时阻止并发；等待过期后明确结果未知，允许显式重试，迟到结果不得覆盖新记录。每轮最多20条记录，不自动删除。

## 结果怎样读

| 输出 | 含义 | 不能推导 |
|---|---|---|
| 模型发现任务偏离 | 至少一项任务要求被模型判为 violated，且任务/答案节选都通过字面校验 | 不是人工确认的错误率，模型仍可能误判优先级或蕴含关系 |
| 模型未发现偏离 | 模型选中的条目均判 met | 不等于任务通过，不保证要求提取完整或事实正确 |
| 未知 | 条目不全/不确定、节选无效、输出未正常结束、超时/预算等 | 不等于0分、失败或通过 |

每条显示原请求节选、答案节选、来源角色及理由。最多8条，由模型选取，覆盖始终 `model_selected_unverified`；`task_success` 始终空，不给成功率、概率或平均分。来源审核的状态仍单列，不与本核对合成一个“置信度”。

## 输入与权限

使用该轮保存的原话、主动任务目标、按序任务更新、历史用户原话以及最终答案。当前明确更正优先，其次任务最新更新、任务目标，记忆只帮助识别。检索线索不是权威任务，来源审核完成和执行 completed 都不是任务成功。

旧任务轮次如果缺 `active_task`，只允许从同用户、同知识库的任务来源轮次原话重建原始目标，并在页面标记 `reconstructed_from_task_source_turn_only`。不借后来更新修饰过去；源目标不可用则保持未知，不调用模型。客户端只能提交 request_id，不能提交伪造答案、目标或审核结果。

接口：`POST /api/v1/conversations/{cid}/turns/{tid}/task-review`，正文 `{request_id: UUID}`。先按所有者/知识库验证，再短事务保存运行占位，模型调用期间不持有数据库锁，最后按执行权写回。不会改变原问答的 question/response/引用或任务完成状态。

## 预算与复现

复用现有 `answer_review_*` 完整输入预算、输出预留、安全余量及审核模型配置。所有请求字符串整体计量，超预算不截断任务来凑窗口；仅 `finish_reason=stop` 可采用。缺供应商usage记未知。核对有独立整轮准入快照，不伪装为原问答已发生的开销。

记录包含完整输入快照、输入/提示/协议SHA256、模型、未固定修订提示、估算/实报、状态、时间和逐条节选。若判断模型和生成模型不同，也只陈述模型名不同，不证明评审独立可靠。

本功能借鉴[Ragas将回答相关性](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/)与[来源忠实度](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)分开处理的思路；没有把反推问题的向量相似度当任务完成。本阶段仍是开发诊断，不能替代M1外审、M2独立标签或C5的独立多轮质量评测。

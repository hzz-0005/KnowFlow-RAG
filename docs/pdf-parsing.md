# PDF 结构化解析与切片检查

当前支持的上传后缀仍为 PDF、DOCX、MD、TXT。多格式和跨文件规则修订需求已登记为[后期优化](complex-document-roadmap.md)，本阶段不实现业务专用流程。

## 运行

```powershell
docker compose -f compose.yml -f compose.pdf.yml up -d --build
```

覆盖文件启用 `PDF_PARSER=docling`、容器内 `http://docling:5001`；宿主机调试可使用 `http://localhost:5001`。基础 `compose.yml` 保持 native 路径，方便不安装模型时运行文字文档和测试。需要保持使用覆盖文件，否则重新创建 API 后会回到基础解析。

镜像固定为 `ghcr.io/docling-project/docling-serve-cpu@sha256:8ff0fd9379a7ec85c2508274dfbaa44e5afb730d38096bf56d95a1338289738d`。本次运行版本：serve 1.37.0、Docling 2.140.0、core 2.103.0。使用异步转换与状态轮询，总超时 600 秒、150 页上限；失败不静默降级。解析服务单 worker、4 CPU、4 GB 内存上限；启动的模型约占 2.2 GB，实际峰值随文档变化。

固定版本的 OCR registry 接受 `iso:zh`，RapidOCR 使用中文识别路径，受控中文扫描页和真实英文 PDF 均已运行。不能把 registry 中列出的语言数量当作已验证的语言覆盖。该版本直接传 `zh` / `zh-Hans` 会初始化失败，因此在适配器中固定了实际验证过的 registry ID。

## 数据和来源

- 原文件仍保存在私有上传卷。`document_blocks` 保存正文树顺序、类型、章节、父引用、文字、表格单元格和来源位置；不保存一个虚构的解析正确率。
- Docling 的底部原点坐标转换为顶部原点的归一化区域。每个 chunk 保留所属块的全部来源区域；预览高亮是块区域，不声称逐字定位。
- 相邻同页、同章节、同父块的正文按 1000 字符预算打包，不固定每篇片数。不同表格不合并，行组保留表头、表注和单位。长内容沿用 120 字符重叠细分。
- 页眉页脚保留供检查，不作为正文索引。图片区域保留，但本阶段不把 OCR 文字自动解释成箭头方向、嵌套关系或图表数值。
- 转换部分成功、正文树未引用内容、没有可检索正文的页和图片语义未核验均产生报告告警。空白页可能触发待核对提示；有文字也不代表整页完整。
- 替换字符（U+FFFD）会按块计数并记录涉及页码，触发需核对告警；缺字尚未自动修复，后续需要针对性 OCR。没有替换字符也不能保证编码和内容正确。
- 解析、embedding 或事务失败时，旧切片/块不删除；文档会标记失败并退出有效检索。重处理成功会替换派生索引及旧图谱，需重新构建图谱。
- 当前没有持久队列和转换缓存；API 重启中断的任务尚不能断点续作。原始 Docling 全量响应的归档、跨页续表合并、图中关系视觉理解留待后续。

## 页面检查

文档卡片 → **查看切片**：

1. “索引切片”展示真实数据库中的内容、顺序、章节、字符数和来源块，不是临时重新计算的演示切片。
2. “原始解析块”展示解析器返回的结构，包含未参与检索的页眉、页脚和图片区域，便于区分解析问题与分块问题。
3. 按关键词或页码筛选，每页 20 条；统计包括整个文档的数量和最短/平均/最长字符数，筛选结果另计分页总数。
4. 点击“查看原页”打开受登录和知识库所有权保护的 PNG，能显示对应区域。JWT 不出现在 URL 中。

**解析报告**列出解析器、块/表格/图片数、逐页文字层字符与索引块字符、告警。字符数只用于排查，不能解释为 OCR 准确率或召回率。旧文档报告缺失时明确显示未核验，不自动重建用户原有文档。

## 表格行定向召回

在真实 PDF 的现场验收中，“Table 1 中 Table 类与 Text 类的 Count”最初因两行未同时进入 top-k 而拒答。为解决同类问题，结构化表格行现在携带第一列原始单元格值和行号；这只是字面检索提示，不将第一列断言为业务主键。

混合检索、混合重排和图文混合额外运行行键召回，并以 RRF 融合。查询明确提到的单元格标签可获得候选；模型仍需通过相关性与引文校验，表格行排名单独展示。纯向量和纯关键词路径保持基线含义。ASCII 标签使用边界匹配，避免把 Text 匹配到 context。相同行名出现在多个表格时仍需结合表注和问题范围判断，不能保证任意问题的完整证据集。

已有结构化表格可从保存的单元格补建提示，无需重跑 OCR、embedding 或修改切片正文：

```powershell
.venv/Scripts/python.exe -m knowflow.app.table_hints --document-id <文档UUID>
```

这是本地管理命令；只对明确指定的文档生效。正文被长切片边界截断时，只补建能完整匹配保存行文字的提示，其他切片保留原有召回路径。新上传和重新解析的结构化 PDF 自动写入提示。

## 页面内的单页 OCR 对照

PDF 文档卡片 → **OCR 对照** → 选择物理页码 → **运行单页 OCR**。页面并排展示已保存的正文解析块与强制 OCR 候选，列出字符、替换字符、正文块和表格块数量，以及数字新增/缺失和出现次数。基线排除页眉、页脚、图片和空分组；不拼接带重叠的检索切片。跨页文字块只有在字符范围完整、无重叠且覆盖全部非空白文字时才按物理页分离。旧索引缺少范围或校验失败时保留整个块并显示警告，不能据此声称单页完整。

文字重合以 NFKC 归一化后的拉丁词元、数字和中文单字多重集合计算，只表示相对基线保留比例。数字变化也是字面检查，可能来自去重、格式、识别或范围变化；二者都不是准确率，更不能证明哪一个结果更正确。候选文字低于基线的 70% 或表格块减少时提示核对，不按阈值自动替换。

任务和结果存入独立的 `ocr_reviews`，可关闭弹窗后回来查看；原文件 SHA-256 校验、用户所有权、物理页码校验仍生效。结果不进入切片、向量或图谱；文档重处理后通过来源块指纹标记历史基线。API 为 POST/GET `/api/v1/documents/{id}/ocr-review?page_number=N`，仅 POST 会触发本地转换。

当前全局最多运行一个对照，重复提交同文档同页会复用正在运行的任务；其他页请求返回繁忙提示。没有持久工作队列，服务中断不会自动续跑，超过转换超时加 30 秒后读取或新提交时会标记失败，允许重试；已完成的结果仍保留。该限制只覆盖本功能，不宣称限制全部文档导入任务。

## 局部 OCR 离线对照

单页强制 OCR 也可用于离线比较，不自动覆盖生产索引：

```powershell
.venv/Scripts/python.exe evaluation/complex_documents/compare_page_ocr.py evaluation/complex_documents/real/2206.01062.pdf --page 1
```

同一真实 PDF 第 1 页，基础结构化路径含 16 个替换字符；强制 OCR 候选降为 0，但正文串长度由 12287 变成 3422，图片内文字与正文的提取范围发生变化。原有索引未覆盖，候选与基线文字分别保存以供核对。“乱码为零”不足以证明整页信息完整，也不能据此自动选择候选。

另用混合样本的第 2 页验证了局部请求仍保留物理页码 2，防止局部转换结果错误指向原文件第 1 页。页范围越界和未启用结构化解析器时请求强制 OCR 都有自动回归。

## 验证命令

固定表格回归集位于 `evaluation/complex_documents/table_queries.json`，包含 3 个正例和 1 个不存在类别的负例。相同语料、模型和 top-k=8，仅切换 `TABLE_ROW_RETRIEVAL_ENABLED` 的单次检索消融，3 个正例的平均 Recall@8 为基础路径 0.0、含表格行路径 1.0；新路径 MRR 为 0.25，Precision@8 为 0.167。说明该小集合的漏召回已改善，但排序和干扰项仍有优化空间。这不是生产准确率或整体能力结论。

负例在两种路径都返回过原始候选；该检索指标不评估回答是否拒答。侧边栏的逐片相关性检测和最终拒答需单独核对。两次单次耗时还受 API 与并发影响，不据此判断稳定性能差异。完整报告保存在 `evaluation/baselines/table-hints-*-20261022.json`。

```powershell
.venv/Scripts/python.exe evaluation/complex_documents/evaluate_pdf_parsing.py
.venv/Scripts/python.exe -m pytest -q
```

真实解析回归包含两份受控样本（混合原生/扫描、纯扫描）和真实九页复杂 PDF。受控样本核对编号、周期、百分比、对象名称；真实文件核对九页均有可检索正文及表格结构存在。这些检查不证明所有表格单元格、阅读顺序和关系都正确。

后端还覆盖：worker 失败、服务不可用、部分成功、漏页、非法页码/单元格、坐标转换、表头单位保持、动态打包、原页与切片的用户隔离、失败重建保留旧来源。前端覆盖不可信文本、归一化区域校验、旧索引提示及实际切片展示。

官方接口和文档模型参考：[Docling Serve](https://github.com/docling-project/docling-serve/blob/main/docs/usage.md)、[DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/)。

## 原页字体与跨页引用

API 镜像已安装 Noto CJK 与 Fontconfig，补齐标准中文 CID 字体未嵌入时的原页预览。曾出现解析文字正常、快照中文消失的实际失败，因此不能只看文字提取结果；新增 CJK 文本区域有墨迹的渲染回归，并完成页面人工核对。这不保证所有损坏字体均可还原。

文档还可查看明确编号的 [文内引用索引](document-references.md)，包括来源和目标、歧义和目标缺失。解析报告显示索引状态，但结构链接唯一匹配也不代表关系语义正确。

## 合并表注与表格候选排序

页内表注恢复、跨页文字字符范围、来源节选和表号筛选规则见 [文内引用](document-references.md)。恢复的表注和表体均保留原页区域；每个打包后的表格切片只保存一次表注。`cell_keys` 来自原始文字单元格，`table_label` 来自明确表注，不推断业务身份或表格续页。

固定回归 `evaluation/complex_documents/table_caption_queries.json` 包含中英文目标行及一个不存在置信区间的负例。负例专门区分 mAP 的 IoU 区间与统计置信区间，检索返回候选不算回答通过，仍需实际问答核对。

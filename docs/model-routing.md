# 首稿生成：路由输入与完整任务分离

合同 `task-route-authoritative-input-v2`，2026-10-25。

当前修复针对首稿生成模型选择：旧版把包含辅助说明的完整任务作为复杂度输入，固定not/version等词会触发复杂路线。现在只在有明确服务器意图对象时使用用户原话作路由判断；预算、生成、相关性与依据核验仍收到此前完整任务，没有截断条件或删除辅助提示。

## 判定信息

内部RoutingInput由服务器构造，不是新的请求JSON字段。来源标记：

- question_text：没有额外会话意图，使用完整问题。
- raw_user_intent：本轮current_user_input及引用历史question、supplements原文；不含turn_id、note或检索线索。
- full_task_fallback：内部意图结构不可用，保守扫描完整任务，不只保留某个看似简单的字段。

不会解析用户原文中的JSON来认领“内部意图”。因此用户直接输入带有not/production的JSON字符串，仍作为普通完整用户文本检查，不能借同名字段跳过复杂规则。

本轮未更改既有复杂规则：命中条件/范围/否定词、用户任务超过3500字符、最终证据超过1个来源时使用复杂生成路线；短关系抽取仍强制复杂路线，审核仍按审核配置。规则是工程启发式，不是难度概率或质量评分。当前及历史原话均保留，已被更正的旧条件也可能让路由保守升级；本包不尝试从原话自动删掉旧限制。

## 预算、请求与轨迹一致

首稿measure_request基于完整answer_messages估算预算，同时按独立RoutingInput计算model_route。plan_answer_context每次整块试放使用同一RoutingInput，最终来源数参与路由。generate_answer直接采用最后一次测量得到的模型/思考设置与输出参数，不另用包装文本重新判定。

API的generation_route复用该决策，保存policy_version、signals、input_basis及路由输入长度/SHA-256。context_budget保存相同决策与其对应的输出限制、完整实际消息指纹和供应商usage。路由输入哈希与完整提示哈希是两回事；不能用前者估算模型真正输入长度。

“首稿预算”展开区可查看模型、思考开关、路由依据与命中的规则；旧结果不补造解释。所有原始条件仍在原意图详情中，仍可能被模型理解错误。输出截断拒答、来源校验和独立审核未因简单路线而取消。

## 评测与限制

新质量报告保存model_routing_contract，包括路由版本、规则指纹、阈值与生成模型/思考配置。不同或历史缺失时，不冒称同模型策略回归；两份均缺失的历史报告保留旧逻辑，不能据此宣称历史配置已齐全。M1冻结账本与旧结果不改写。

没有新key、模型替换或数据库迁移。相关性判断、审核和纠错的路由没有在此统一，因此首稿少用复杂模型不等于整轮必然提速或降费。独立难度/语义标签不足；控制与真实页面结果只按各自范围陈述，见 本轮验收（本地研究记录，未随公开包分发） 与 外部依据（本地研究记录，未随公开包分发）。

# 会话、任务与长期记忆：已交付范围

## 三种状态各负责什么

| 类型 | 存储 / 读取触发 | 写入触发 | 不承担什么 |
|---|---|---|---|
| 短期会话 | PostgreSQL conversations / conversation_turns；按最近已验证话题读取最近8轮、最多3条完整意图，载荷3000 token并计量完整请求 | 每次发问原子保存原话、解析、结果、预算与引用版本；刷新恢复 | 不把所有历史或旧模型答案塞进新提示；没有自由生成的事实摘要 |
| 任务记忆 | task_memories + task_memory_attempts；用户在检查点中选择跨会话恢复 | 有效静态多步计划自动建检查点；任一结束轮次可点击保存；恢复、失败、取消及尝试链持久化 | 不等于后台执行队列；不声称依赖查询/计算已经逐步执行 |
| 长期记忆 | user_memories；用户 / 当前知识库命名空间；当前问题名称字面匹配、表达偏好按需加入 | 管理页显式保存/启用；明确“记住：…”或“remember:”前缀自动形成候选 | 用户备注不是文档事实；没有从所有聊天静默抽取事实、自动覆盖、无限语义搜索 |

本版复用 PostgreSQL + SQLAlchemy，无新模型、向量库或编排依赖。已有知识向量仍走原 pgvector；低数量偏好/别名采用类型和名称匹配，方法明确标记。未做大规模记忆性能或语义召回成绩。

## 怎样使用

1. 正常在聊天区追问。本轮原话、排除/范围/时间及明确更正保留，来源重新检索；点击逐轮详情查看上下文、任务和记忆记录。
2. 在回答下方点“保存任务”，或完成有静态多步计划的问题后，打开右侧“任务检查点”。查看目标、原话条件、依赖与尝试，点“在新对话恢复”。输入区显示恢复目标，可补充更正或取消本次恢复，再发送。恢复是新的付费查询，不是播放旧答案。
3. 在右侧“长期记忆”添加对象别名或用户备注。名称是匹配词，如“我的测试归档”，内容写明确对象，如“PineVault staging archive”。选择“启用”后，未来包含该名称的输入可以召回。候选默认不生效。
4. 表达偏好仅支持 `response_style` = `concise` / `standard` / `detailed`，分别简洁/标准/详细。本轮明确要求优先，不可为简洁删必要事实或来源。不存自由系统指令和任意输出语言开关。
5. 可更正、停用、设有效期或删除记忆。有效期必须带时区且在未来；过期项保留可查看但不召回。删除实际移除记忆行，后续请求不再加载。已经发送的请求和历史对话/用户原话不追溯改写，也无法从供应商处撤回。

## 召回与上下文预算

- SQL 先按所有者及 namespace 过滤，再按有效状态/有效期和名称匹配；拉取上限100个匹配项。超上限不偷选前100，返回空选择并记录限制。
- 拉丁名称有词边界，中文名称按字面包含；不把它称为同义理解。相同名称的不同对象线索冲突时要求澄清，不按时间或全局/项目优先级猜一个。表达偏好冲突不采用该偏好。
- 记忆装配最多4项、估算800 token；整项接纳或跳过。上下文解析仍受载荷3000、完整输入/输出预留和整轮累计预算约束；最长近期意图装不下时澄清，不能用更早的小条目代替。
- 最近原始意图优先，然后相关记忆，再较早历史。模型可从实际提供的 ID 中选择指代线索。记忆“被选择供考虑”不等于已被模型引用，记录 `referenced_ids`；没有独立语义正确保证。
- 主动恢复任务时显式携带 `active_task.goal` 和按序用户更新；当前明确更正、任务最新更新、保存目标依次优先。别名/备注单列 `saved_memory_clues`，仅帮助识别，不覆盖任务范围。实际验收曾暴露平铺上下文导致旧别名范围覆盖生产目标，已保留首次失败并针对该机制修复。
- 恢复检索输入同时保留原任务的已收到补充和按序保存的用户更正，而不只给回答侧传更正。`task-resume-ordered-retrieval-v3`记录更新数量和输入策略；原目标/旧检索线索保留身份，明确后项及当前更正优先。超过4000字符则不派发截断查询，保留原状态并提示取消本次恢复，以完整条件新建问题或检查点；当前没有自动语义压缩。已冻结旧记录不回填为新协议。
- 新增来源结果标识 `turn_id:source:n`、文档/片段ID、序号、来源节选，只从版本仍匹配的真实引用构造。不提供旧回答全文。第2个来源是来源序号，不能假装已确定来源中的第2笔交易或实体。
- 旧轮次依赖的记忆更正/过期/删除后，该轮的解析线索不能重新带回旧对象，转为要求重述。持久用户原话不因此删除。
- 依赖追溯到继承原话中的记忆ID/修订，不能仅检查本轮直接召回的条目；任务的省略目标保留检索线索，但记忆失效后弃用该旧线索，改用原话与当前有效别名重新检索。历史只助识别，来源版本变化仍重查文档。

## 任务的可靠性与限制

检查点保存目标、用户原话条件、静态计划、来源版本、原轮次状态、待补充项；每次恢复保存结果轮次身份、拒答标志和来源版本。恢复前比对来源版本，变化/缺失列出，并重新检索当前知识库；旧引用不进入新证据。

会话锁、任务锁、期望修订号和唯一请求标识共同防止重复派发。一个任务同时只允许一个有效尝试；租约过期后可另开恢复，记录前次 interrupted 和 retry_of。失败不当作成功，缺用量不填0。取消设置任务围栏，迟到结果保留在尝试/对应轮次，但不能覆盖已取消或已被新尝试接管的任务。取消不保证撤销远程请求或计费。

`completed` 只表示一次在线执行返回，包括可能的拒答；每次 `refused` 单列。`semantic_quality` / `step_coverage` 都为 unknown / unverified，没有借执行完成宣称任务语义成功。

本版恢复重新执行完整只读检索，不自动从中间步骤驱动工具、跨文件计算或执行外部副作用。依赖关系是可查看的计划，不是虚构的执行进度。后续有真实需求再实现可验证步骤输出、工具幂等/副作用恢复，不能靠旧模型答案充当依赖结果。

## API 与迁移

- `GET/POST /api/v1/knowledge-bases/{kb}/memories`；`PUT/DELETE .../memories/{id}`。更正/删除带 `expected_revision`；PUT 不允许跨 namespace 移动。列表每页50项。
- `GET/POST /api/v1/knowledge-bases/{kb}/tasks`（POST 来源轮次ID，重复返回同一检查点）；`GET /api/v1/tasks/{id}`；`POST .../cancel`。
- 原会话 `POST /api/v1/conversations/{id}/turns` 新增可选 `task_id` / `task_revision`。它们进入请求指纹。任务、目标知识库和用户三者必须一致。
- `0012_task_user_memories` 增量创建3表，不改写旧轮次或索引。用户/知识库删除有级联，来源轮次保持外键约束。普通输入不能伪造 `_intent_context` / `_response_style` 等私有服务端字段。

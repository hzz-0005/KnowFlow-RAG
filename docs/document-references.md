# 文内编号引用与跨页证据展开

更新：2026-10-22。

本阶段实现的是明确编号的结构链接，例如“见表 2”“参见第 3 节”“see Section 2.1”。它不等于知识关系推断、代词消解、跨文件规则整合或完整图理解。当前支持阿拉伯数字编号及 A1/A.1 类编号；不自动补全省略的编号列表、范围或中文数字编号。

## 观察和核对

文档卡片 → **文内引用**，可查看引用原文、来源块、目标锚点、各自物理页和区域。支持按唯一匹配、同号歧义、目标缺失、外部引用未消解筛选，分页展示；来源与目标正文仅展示节选，完整内容仍由“查看切片”检查。

新入库和成功重新解析的文档自动建索引。旧文档点 **更新引用索引** 即可从保存的解析块补建，无需重新 OCR、embedding 或图谱构建。操作仅重建本功能的结构链接；会在解析报告中记录版本、总数、状态数和预算截断标记。

`document_links` 保存文档、来源块、目标块、原始编号引文、字符位置、解析状态和候选锚点。来源和目标用同一文档的组合外键约束；重新解析时旧块与旧结构链接在同一事务中替换，失败不删除旧来源。

## 唯一匹配规则与边界

- 表号来自结构化表格关联的表注，或严格受限的页内表注恢复；一个游离标题不能冒充表体。重复保存的表注不会产生两个目标。
- 图号定位文字图注，不把图片中的箭头、数值或嵌套关系当作已理解。
- 章节号来自解析器明确标记的章节标题。章节层级识别错误、缺失或标题没有编号时，仍可能无法正确定位。
- 全文同号目标多于一个时保留歧义，不按最近页自动消歧。明确提示外部/其他文档的引用不连向本地同号目标；隐含外部引用仍可能漏判。
- 只扫描正文、列表和图注等文字中的明确引用；表格单元格内的引用、括号子图编号和没有编号的指代暂未展开。
- 每文档最多 2000 处引用；歧义候选每处最多保留 20 个。达到上限会标记索引非全量；不会因为裁掉候选而将歧义升级为唯一匹配。

## 查询时展开

页面勾选 **补充文内引用证据**，或 QueryRequest 的 `expand_references=true`（默认），且服务设置 `REFERENCE_EXPANSION_ENABLED=true`（默认）时启用。基础召回策略和 top-k 不变，展开后的候选追加在其后。

从基础排名前 3 个片段出发，必须在当前切片中实际包含对应编号引文才会展开，防止把同一长块的其他切片也全部视为引用来源。目标限同一有效文档和知识库；表格取带来源块 ID 的行切片，图取文字图注。章节按明确编号的区间取候选，包含下属编号，遇到下一个非下属的编号标题停止；不因一个无编号的误分类标题提前切断。当解析器的标题路径在区间内变化时，会提示范围需核对。这是候选提议规则，不断言所有内容都真正属于同一语义章节。候选按问题词重合分配预算，重合不是置信度。

最多 2 跳、32 次引用检查、8 个新增切片；每个引用最多取 4 个目标切片，每个章节最多检查 40 个正文块。循环按片段和引用 ID 去重。预算不足会明确提示证据链可能不完整。展开路径在检索追踪中显示来源切片、编号、原始引文和跳数；展开切片没有伪造的向量相似度或知识图谱分数。

所有候选继续经过原有逐片相关性检查、精确引文校验、上下文预算和最终引用 ID 校验。展开成功不能证明语义链正确；被相关性检查拒绝或预算裁掉的片段不算已提供给模型。尚未实现自动验证所有必要证据都齐全的通用推理器。

## 合并表注的修复与来源范围

Docling 可能把上一页正文和下一页表注合并成一个文字块。现保留原始字符范围 `raw_charspan`，并在清理空白后保存可精确定位的 `text_range`。仅当这些范围不重叠且覆盖全部非空白文字时，才按范围拆到各物理页；原始块全文保留。验证失败时保留全文和全部来源并告警，不根据页数等分文字。

表注恢复只接受页内文字范围开头的 `Table N:` / `表N：` 等明确编号加冒号。要求同页、不重叠、横向覆盖至少较窄区域的 80%、间距不超过页高的 6.5%，且中间没有同栏内容。表注和表体须互相唯一；两张相邻表、两个表注、不同栏、已有转换器表注等情况均不新增关联。不跨页猜续表，也不改写单元格。

恢复依据存入表格 `structure.caption_recovery`，包含原文字块、清理后字符范围、逐字表注与原页区域；建立结构链接时再次校验文字和来源。表注自己的定义不计作一次正文引用。页面显示恢复提示，并提供同时高亮表注和表体的核对按钮。

表格行带上表号和文字单元格提示；显式询问某表时，额外的行检索通道按表号筛选，再按单元格字面命中和问题词重合排序。向量和关键词通道仍保留；没有表号元数据的旧索引保留原行键回退，不能因此声称其表号已确认。同号跨文档仍可能有歧义。这些都是排序提示，不是概率置信度或实体身份判断。

每个打包后的表格切片只保留一次完整表注，所有行和来源区域仍保留。引用展开同时检查切片的来源字符范围，避免同一跨页块中的表注错误触发上一页的同名正文引用。引用检查器节选和单页 OCR 对照也使用完整校验后的页内范围。

旧索引没有保存字符范围时，需要重新解析才能获得上述修复；只点“更新引用索引”不会重新 OCR 或凭空恢复字符范围。已保存表号的表格可用 `knowflow.app.table_hints` 更新排序提示，不重新 embedding。

## 评测

```powershell
.venv/Scripts/python.exe -m knowflow.app.evaluate_retrieval --knowledge-base-id <UUID> --strategy hybrid --top-k 1 --dataset evaluation/complex_documents/reference_queries.json
.venv/Scripts/python.exe -m knowflow.app.evaluate_retrieval --knowledge-base-id <UUID> --strategy hybrid --top-k 1 --dataset evaluation/complex_documents/reference_queries.json --expand-references
```

基础 Recall@K/MRR/nDCG 仍只看基础 top-k。新增 `candidate_evidence_recall` 和 `candidate_complete_evidence_set` 单独计算展开候选池对标注证据的覆盖；汇总字段带 `candidate`。它们发生在相关性检查和生成预算之前，不是回答准确率或最终进入模型的完整证据率。最终回答及实际上下文仍需侧边栏或 Query API 验收。

受控正例在物理页 8 引用页 4，页 4 再引用页 2；反例在页 2、5 放入重复编号，不能任选一个目标。所有事实均为测试数据。真实复杂 PDF 的结构链接也必须核对，不能把“唯一匹配”当作人工标注正确率。

## 引用编号校验自查

现场问答曾出现模型漏抄 UUID 字符的引用；固定 36 字符的扫描规则未识别它。已扩展疑似编号校验，混合正常引用与错误引用时整体拒绝，且不按相似度猜配。生成端现在只给模型短来源标签，由程序按当前证据列表精确映射到切片 ID；未知标签保留为校验失败，不自行补救。这减少抄写错误，但不替代逐断言的语义忠实度检查。

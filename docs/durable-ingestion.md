# 持久批量摄入（M3-C 首版）

页面上传现在走持久批任务，一次选择 1–20 个 PDF/DOCX/MD/TXT/CSV/XLSX。任务接收后即可关闭页面；API 服务继续处理，页面重新打开后从数据库加载状态。无需逐文件审批。

## 每个文件都有独立结果

状态为 `queued / running / retry_wait / completed / failed / skipped / rejected`。阶段为读取校验、解析、分块、向量化和提交索引。批次摘要同时列出处理中、完成、失败、拒收和重复跳过，不能只写“部分失败”。

空文件、不支持类型或超出预算的文件记为拒收；同库内容哈希重复则跳过并指向已有文档。损坏文件解析失败，其他文件继续。失败摘要包含文件名、阶段、原因、尝试次数和失败页清单；解析器未明确报告失败页时标未知，不从总页数推造失败范围。知道页号但没有页级原因时也明确标未知。

“查看批任务”可查看最近 10 批和各次尝试，包含尝试 ID、重试来源、阶段、错误及嵌入模型。执行完成不表示解析正确、回答正确或质量验收通过。

## 恢复与重试语义

- 数据库保存批次、文件作业和每次尝试。`FOR UPDATE SKIP LOCKED` 领取作业，45 秒租约、10 秒心跳；租约失效后可由工作进程接管，并把上次尝试记为中断。
- 失去心跳时取消本地旧处理任务；提交索引前再次核对租约令牌，并将索引替换和作业完成放在同一事务。过期工作进程不能覆盖新索引。
- 暂时网络故障、超时、限流及服务端错误可自动重试，退避最多 60 秒，每轮最多三次。格式/数据错误不自动反复重跑。手动重试追加最多三次预算，单文件累计最多九次，原历史保留。
- 重试先校验原文件哈希，再尝试复用完整且指纹匹配的解析缓存；缓存不存在或失效才重新解析。每次尝试保存源哈希、解析/分块配置和嵌入模型快照，不保存 key。
- 默认每个 API 进程一个摄入工作协程，可通过 `INGESTION_WORKERS` 设置 1–4；单次尝试默认 1200 秒上限，可用 `INGESTION_ATTEMPT_TIMEOUT_SECONDS` 设置 30–3600 秒。多 API 进程的总并发为各进程之和。
- 上传及手动重试共用 200 个活动作业的背压检查。本批读取预算 100 MiB，单文件还受已有上传上限约束；先前已接收的正常文件不会因后一个文件超限被丢弃。

这是 **至少一次处理、受租约保护的提交**，不是外部 API 恰好调用一次。进程在远程调用期间中断时，供应商可能已收到了请求，恢复后可能重复计费。当前仅缓存完整解析结果，尚无逐页续作、嵌入向量断点缓存或图谱持久作业；不声称解决任意坏页恢复和全部无人值守问题。

数据库和文件系统不是同一个事务；进程在原文件落盘后、数据库提交前崩溃，可能留下未引用的原文件。它不会成为可检索文档，自动孤儿文件清理尚未实现。成功索引仍按既有事务替换，失败不覆盖旧切片；失败状态文档不参与当前检索。

## API 与兼容范围

| API | 用途 |
|---|---|
| `POST /api/v1/knowledge-bases/{id}/ingestion-batches` | 多个 `files` multipart 字段；可带 `Idempotency-Key` |
| `GET /api/v1/knowledge-bases/{id}/ingestion-batches` | 最近批次及逐文件摘要，默认 10 批 |
| `GET /api/v1/ingestion-batches/{id}` | 摘要及所有尝试记录 |
| `POST /api/v1/ingestion-batches/{id}/retry` | 只重试有剩余累计预算的失败作业 |

相同知识库与请求键、相同文件清单返回原批次；相同键提交不同清单返回 409。不同请求键但文件相同仍按内容哈希跳过，不重复建索引。全部入口验证知识库所有权；其他账号不能读取或重试。

旧 `POST .../documents` 单文件 API、重新解析、重新分块和图谱接口继续兼容，仍是原有进程内后台任务，**没有在本次自动改造成持久作业**。批任务活动期间禁止并发启动旧重新解析/分块，防止两条流程争写同一文档。部署不会收养或自动重建历史遗留的 pending 文档。

迁移为 `0010_ingestion_jobs`，仅新增三张表，不改历史评测结果或既有来源。部署仍使用 Compose；不要删除数据库/上传卷。

## 验证入口

专项测试覆盖混合批次、权限、请求幂等、并发重复提交、缓存复用、自动/手动重试预算、容量背压、截止时间、删除文档、中断恢复、旧租约提交保护和心跳丢失。临时数据库另验证完整迁移、回退再升级和模型一致性。

侧边栏控件与实际记录见 本次交付（本地研究记录，未随公开包分发）、[故障样例清单](../evaluation/batch_v1/manifest.json)。样例仅用于软件流程验证，不是 M2 语义金标。

数据库锁选型依据：[PostgreSQL SELECT 文档](https://www.postgresql.org/docs/current/sql-select.html)说明 `SKIP LOCKED` 可用于多消费者队列；它本身不提供业务层恰好一次保证，租约、重试和提交保护由本项目实现。

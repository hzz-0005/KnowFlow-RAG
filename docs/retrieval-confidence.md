# 每次检索的片段相关性检测

已实现的是“候选片段是否与当前问题有关、是否值得进入回答上下文”的检测。它不是来源真实性鉴定，也不是回答正确概率。

## 页面怎么看

每次提问后，回答下方会出现“检索相关性检查”。展开可查看本次全部 top-k 候选，而不只是答案最终引用的片段。每条显示：

- **直接相关**：给出了所问事实，主体、版本、环境等匹配。
- **部分相关**：包含必要定义、条件或多跳问题中的一步，单独不足以回答整道题。
- **仅背景**：主题接近，但没有所需事实。
- **不相关**：没有可用证据，例如答的是另一个对象或版本。
- **未核验**：检测失败、返回格式不合法、引用无法在原文找到，或超出检测预算。

还会显示判断理由、逐字校验过的支持引文、章节/页码、原始检索分数，以及“已引用 / 已提供给模型 / 未采用”。引用卡片也显示相关性与可用的余弦相似度。

余弦相似度来自实际向量召回；关键词/图谱策略没有向量分数时不会补造分数。多问句的相似度可能来自召回时的一个子问。排名、RRF 分数、重排分数也不能当作正确率。

## 执行逻辑

1. 先按原策略召回 top-k 候选。
2. 把这些候选放在同一次 MiMo 结构化检查请求中，要求逐条判定并引用原文；检查不会为每条候选单独发请求。
3. 服务端核对来源 ID、唯一性与引文。缺失、重复、伪造或无依据的“相关”不能被提升成已核验。
4. 默认只有直接相关和部分相关的片段进入生成上下文。背景、不相关和未核验片段不参与回答；全部不可用时拒答，并展示候选与原因。
5. 生成上下文被预算裁剪时，若裁掉了已核验的支持引文，该片段不算已提供给模型；回答中的伪造来源也会被拒绝。

相关性判定本身由模型完成，可能误判。逐字校验只证明引文确实存在，不能证明模型对它的语义理解一定正确。部分相关也不代表所有问题分支、跨页条件或整条推理链已经找齐。

## 配置

默认启用，不需要新增 Key。复用现有 LLM 配置：

```dotenv
RETRIEVAL_ASSESSMENT_ENABLED=true
RETRIEVAL_ASSESSMENT_TOKEN_BUDGET=12000
```

一次有候选的正常问答会增加一次批量检查调用；耗时记录在 API 的 `retrieval_diagnostics.assessment_latency_ms`。检查不可用时明确标为未核验，默认不继续用这些片段生成答案。关闭检查可恢复基线生成路径，页面仍显示未核验，不能把关闭状态说成通过。

## 回归怎么跑

`evaluation/relevance_cases.json` 是原创合成标注集，共 12 类场景、24 个问题-片段对，包含跨语言、错误主体/环境/版本、多跳子证据、远页定义、否定与条件、无答案、提示注入、歧义和乱码。标签在运行模型前已固定，不是让被测模型自己生成标准答案。

```powershell
.\.venv\Scripts\python.exe -m knowflow.app.evaluate_relevance `
  --strict `
  --output evaluation/results/relevance-current.json
```

与固定历史结果比较，先确保没有修改输入集，再执行：

```powershell
.\.venv\Scripts\python.exe -m knowflow.app.evaluate_relevance `
  --strict `
  --baseline evaluation/baselines/relevance-v1-mimo-20261021.json `
  --output evaluation/results/relevance-current.json
```

输入数据哈希不同会拒绝比较；以前通过的采纳判断变差会返回非零退出码。`--strict` 还要求本次所有采纳/不采纳判断符合固定标签。报告分别记录误采纳、漏采纳、未核验、采纳精确率和相关证据召回；细分类别与预期类别的差异也会保留。格式/伪造来源/检测错误/预算丢失等由不依赖在线模型的自动测试覆盖。

2026-10-21 首轮真实 `mimo-v2.6-pro` 运行中：24 对的采纳/不采纳判断均符合标签，误采纳 0、漏采纳 0，乱码 1 对被标为未核验。这个集合小且人工构造、正负各半，不能据此推断真实资料上的精确率，更不能宣称“置信度已校准”。

同日侧边栏手动验收：HNSW 维度问题的 8 个候选中，1 个直接相关被引用、3 个背景和 4 个不相关未采用；没有价格依据的问题虽然命中 8 个候选，仍全部排除并拒答。截图保存于 `evaluation/results/retrieval-relevance-positive-20261021.png` 和 `evaluation/results/retrieval-relevance-refusal-20261021.png`。这些是功能验收实例，不代表总体检索指标。

## 概率校准的边界

当前不输出“90% 正确率”一类数字，`calibrated_probability` 保持空。要提供概率，必须另收集足量真实问题与召回片段，由人独立标注，分开训练/校准/测试集，并按来源文档或主题划分以避免泄漏；再验证可靠性曲线、Brier/ECE 和拒答阈值。用同一个小型回归集拟合再在原集报告成绩不算校准。

复杂 PDF 的 OCR、阅读顺序、表格和跨页证据能力仍按[复杂文档路线](complex-document-roadmap.md)推进。片段相关性检查不能恢复已经被解析器丢掉的内容。

本轮自查还修复了引用格式漏检：生成端改用短来源标签，程序精确映射回当前证据的真实切片 ID；漏字符的 UUID 类标记和未映射标签均不能与正常引用混过校验。模型仍可能将正确来源引用在错误断言后，逐断言的语义支持检查与人工抽查仍需继续完善。

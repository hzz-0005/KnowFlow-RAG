# CSV / XLSX 摄入与来源核查

本次交付对应总方案的 M3-A 首批格式适配。与现有 PDF、DOCX、Markdown、TXT 共用上传、知识库隔离、结构分块、向量/关键词索引和引用流程。无需逐文件批准才能入库；解析报告的“需核对”是抽检提醒，不是审批闸门。

## 自动处理与可观察结果

- CSV 支持 UTF-8（含 BOM）、带 BOM 的 UTF-16、GB18030；识别逗号、分号、制表符、竖线及 `sep=` 指令。保留带引号换行、前导零和实际列数，不把空值补成零。
- XLSX 遍历全部工作表，包括隐藏工作表与隐藏行。保留工作表名、行列坐标、原值、存储值/类型、数字格式、合并区域与公式信息。隐藏内容纳入索引会在报告和单元格检查中说明。
- 空行分隔数据区域；按行生成结构单元，再由已有 token 预算分块。同一区域可自动形成多个切片，不设每文件固定数量；不同工作表不混块。超长行可能分片，保留坐标。
- 表头是候选上下文：从区域前几行推断列名，合并表头可附下一行。所有原行保留，候选表头带来源范围及 `candidate_not_verified` 标记；复杂多层表头语义仍可能推断错误。
- 单元格以 `工作表 + A2:D2` 定位，无固定 PDF 页码。引用保留这些来源；点击“查看表格来源与原值”，在“解析块”展开单元格检查，可分页查看原值、格式、公式与缓存状态。切片检查也可直接切到“解析块”。

## 公式与数值边界

不启动 Excel，不执行公式，不刷新外部链接。公式文本与文件保存的计算结果分开存储：

| 状态 | 含义 |
|---|---|
| `not_formula` | 普通单元格；CSV 中 `=1+1` 仍是原始字符串 |
| `missing` | 未保存公式结果，索引明确写“未知，未计算” |
| `available_unverified` | 文件里有缓存，包括数值零或空字符串；可能过期，未验证 |
| `cached_error` | 缓存为 `#DIV/0!` 等错误，显式标错，不作为正常数值 |

合并子格保留自身原值为空，同时标明继承的锚点。一般空白、数值零、CSV 空字符串与缺失公式结果分别保留。简单补零和百分比格式可读化；任意复杂 Excel 显示格式不保证完整还原，因此原值、存储值和数字格式均可检查。

## 失败与资源限制

当前上限：64 工作表、50,000 行、256 列、200,000 已用区域单元格，XLSX ZIP 展开 50 MiB/10,000 成员，累计文字 500 万字符。较稀疏但有远端格式的工作簿也可能触发已用区域限制。达到上限或文件损坏时明确失败，不截取前 N 行冒充完整解析。合并区域先检查再交给解析库展开；XML 使用 defusedxml。

解析缓存包含适配器版本，支持不重新解析的“重新分块”。嵌入失败保留旧切片；失败文档不参与当前检索。原有 PDF 等格式的缓存指纹未改变。

当前不支持旧版 XLS、XLSM、加密工作簿；不解释 Excel 图片/图表（报告会提示遗漏），不保证任意多层表头自动语义还原，也不提供跨文件任意计算或版本规则决策。此工作包不等同于持久批任务已完成。

## 验证与证据

- 自动检查入口：`python -m pytest -q`、`node --test frontend/tests/*.test.mjs`；Windows 可用本次证据目录的 `run_checks.py tests` 展开文件列表。
- [合成控件样例](../evaluation/tabular_v1/manifest.json)：库存 XLSX（含隐藏维护表、合并表头、零/空白/缺失公式缓存）和工单 CSV（含前导零、跨行字段）。它们是软件测试控件，不是独立语义金标，也不加入冻结的 M2 数据。
- 验收与运行记录（本地研究记录，未随公开包分发）：区分自动测试、真实 API、页面手测及历史指纹核查。

实现依据：[openpyxl 读取参数](https://openpyxl.readthedocs.io/en/3.1/api/openpyxl.reader.excel.html)说明 `data_only` 读取上次保存的值；[官方安全说明](https://openpyxl.readthedocs.io/en/stable/index.html)建议使用 defusedxml。缓存存在不代表已经重新计算。

# 自然口吻的浏览器测试

页面验收不能长期只问同一组标准题。固定回归用于检查旧问题；新探索用于发现尚未覆盖的问题，两者记录分开，不拿旧题通过替代新失败排障。

## 每包怎么选题

- 先选资料和可核对出处，再冻结新问题、会话顺序与预算，不能先看答案再改题。首问也允许缺对象，预期可以是澄清而非回答。
- 同一个资料点覆盖不同表达：口语、长前言、简称/错字、同义词、否定范围、数字单位与更正；不能只换一个同义词就宣称泛化。
- 按真实会话串联：建立对象 → 省略追问 → 补充/纠正 → 话题切换 → 回到前对象。至少保留一次澄清后补充和一次待澄清期间换话题。
- 同时有缺证据、歧义多候选、库外能力与跨语言输入。不要求无依据问题强行回答；要看缺什么、是否正确提示、能否从来源列候选。
- 在不同资料包轮换开展探索，覆盖自然文档与合成控制。以后增加扫描/杂乱PDF、表格文件、跨文件版本冲突时先明确原文标签，不假装现有PDF/TXT能代表所有格式。

## 侧边栏怎样执行

1. 记录账号作用域、知识库/文档版本、模型配置指纹、实际页面脚本版本和部署指纹。检查空草稿、无进行中请求；过旧脚本先刷新，再开始新包。
2. 各组新建会话，同组三轮以上保留上下文。使用页面输入框与发送按钮，每条一次；按持久结果确认请求完成再发送下一条。
3. 保存原始轮次、实际改写、候选/排序/引用、阶段失败、调用与usage。页面截图与本地只读数据库采集分别标来源，后者不冒称浏览器下载。
4. 登录过期或等待超时先确认是否已落库，不能再次提交同题来制造较好的结果。故障、拒答、澄清、unknown都留账；修复后另编号，不覆盖首败。
5. 同时看页面最终回答和详情。检索对但模型乱编、模型未获证据、指代选错、接口故障、展示旧脚本是不同原因。

用户于2026-10-26明确要求：**每包修改完成后，重建并重启前端UI，确认正在运行最新版本再测试。** 前端构建后重建镜像、强制重建frontend容器；需要后端改动时同时部署api，不动db/docling卷。确认无进行中请求或未保存输入后刷新侧边栏，读取实际script版本；使用`scripts/verify_frontend_assets.py`核对HTTP提供的index/app/CSS/bundle SHA-256与当前文件一致，保存版本/指纹结果。容器重启、页面刷新、版本与内容指纹缺一不可；只看到Docker启动或HTTP 200不算完成。

## 怎样下结论

- completed是执行状态，可能是拒答；needs_clarification也可能是合理处理，不按HTTP状态或完成数推成功率。
- 前一轮没答出来会影响追问依赖，后续失败注明依赖受损，不能全部归到检索召回。
- 引用存在不等于语义全部正确。开发者逐题观察与独立标注分开；没有gold或独立语义审核时保持unreviewed。
- 工程回归、开发探索、保留集各用独立清单。用过并据其修复的题不再叫盲测；之后新增相似题测试迁移。

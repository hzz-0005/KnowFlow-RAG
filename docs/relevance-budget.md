# 检索相关性检查的完整请求预算

合同 `relevance-window-whole-passages-v1`，适用于候选检索后的相关性检测，不是全链路上下文窗口管理。首稿生成仍按 [原合同](answer-budget.md)；查询解析、改写、答案复核/纠错及长期/任务记忆的剩余范围见总方案。

## 输入和候选

完整系统提示与用户任务（包括会话中明确引用的原始条件）、候选JSON的ID/分隔开销、输出预留和安全余量一并计入。提示内容沿用relevance-v2-workflow-scope，原模型分配规则不改。本地Qwen tokenizer与聊天封装仍是估算，不能称为供应商真实窗口或真实计费用量。

按原候选顺序整块试放；整块不合预算则跳过，并继续尝试后面的较小块，不截半句、表格或尾部限定。相同正文而身份不同的候选分别检查；重复ID的全部输入保持unknown，避免把一份判断套到冲突内容。单次最多30个身份，对齐原响应schema；超出、空片段或预算跳过均保留原候选轨迹及未检查原因。

完整固定输入本身超预算，或没有候选可整块装入时，不初始化/调用检测模型。该阶段候选仍为unknown，不等于不相关；正常开启相关性检查时，无可用证据会沿原链路说明证据不足，而不是绕过检查直接交给生成模型。

## 输出、错误与可观察性

请求显式发送输出上限。共享原首稿的供应商字段适配，已核对端点/模型使用对应字段；自建兼容端点保持输出语义unknown，不只凭模型名宣布已验证。

只接纳finish_reason=stop。length、过滤、缺结束标记或其他未正常结束的正文，即使包含可解析JSON也不采用；正常结束后仍需响应结构、ID及逐字引文校验。合法响应中缺项、重复或伪造引文不变成已验证相关。供应商异常不输出原异常文本，避免泄露配置与原文；不会为出分重问同一题。服务SDK的既有重试配置未在本包全局更改，真实独立控制额外明确关闭自动重试。

`retrieval_diagnostics.context_budget` 保存计划装配/跳过决策、正文与实际提示SHA、估算值、模型、输出字段/范围、是否发起/收到响应、正常结束状态、实报usage和原因码。装配数不是收到可用判断数；unknown独立统计。缺usage不填零，不保存思考正文。页面“候选证据”面板展示这些区别，旧轮次无字段则保持未知，不通过重跑补造历史。

## 可选配置和比较

实际.env无需改写、新增key或换模型；默认值与.env.example如下：

| 配置 | 默认 | 含义 |
|---|---:|---|
| RETRIEVAL_ASSESSMENT_TOTAL_TOKEN_BUDGET | 32768 | 本阶段估算运行目标 |
| RETRIEVAL_ASSESSMENT_OUTPUT_TOKEN_BUDGET | 4096 | 预留并请求限制的输出 |
| RETRIEVAL_ASSESSMENT_SAFETY_TOKENS | 1024 | 封装/分词偏差缓冲，不保证覆盖全部误差 |
| RETRIEVAL_ASSESSMENT_OUTPUT_PARAMETER | auto | 使用既有受支持供应商适配；未知兼容服务明确标记 |
| RETRIEVAL_ASSESSMENT_TOKEN_BUDGET | 12000 | 候选在完整请求中的估算增量上限 |

公式：估算输入+输出预留+安全余量≤运行目标，且证据增量≤候选上限。固定任务不截断；实际模型窗口和输出语义需供应商验证。大而重要的候选可能被全部跳过，输出额度也可能导致整批未完成；本包不承诺召回、语义质量、时延或成本必然改善。

新质量报告记录relevance_budget_contract；合同或额度不同，或一侧历史未记录，返回not_comparable。两侧均无新合同的历史兼容路径不回填本版假设。未改M1冻结账本、金标、保留集及用户索引。本包记录（本地研究记录，未随公开包分发）。

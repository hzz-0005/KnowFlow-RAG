# 解析与切片自动诊断

在文档操作栏点击“自动诊断”。接口 `GET /api/v1/documents/{id}/diagnostics` 只读现有解析块和切片，按知识库所有者鉴权；不读取原始文件、不解析/OCR、不请求 embedding 或 LLM、不写数据库，也不重建索引。旧文档可直接使用。

## 本版检查范围

| 检查 | 实际含义 | 限制 |
|---|---|---|
| 来源列表与块关联 | 没有来源、来源项格式错误、指向不存在的块 | 来源存在不等于来源正确 |
| 字符区间、页码、归一化矩形 | 检查区间格式和边界、PDF 页数边界 | 没有字符区间为未知；不检查语义蕴含 |
| 表格定位 | 工作表名、Excel A1 范围合法性与坐标上限 | 不重算公式，不判断标题识别正确性 |
| 页覆盖 | 保存页数与切片来源中出现的页对照 | 缺来源可能为空白页、图片、解析遗漏；不是文字覆盖率 |
| 解析块引用 | 非空且非图片/页眉/页脚的块未出现在切片来源中 | 可能是有意排除；不声称字符级丢失 |
| token 预算 | 用匹配的 tokenizer 指纹，重算正文加章节前缀，比较保存的 max_tokens−token_reserve | 历史配置缺失或指纹不匹配为未知；计数仍是估算，不是供应商计费值 |
| 异常字符、相同正文 | 检出 U+FFFD、正文完全相同的切片 | 替换字符未必是 OCR 错；相同正文可能为正常重复上下文，不自动删除 |
| 来源文字与节选 | 对已有来源块 text_range 与切片 chunk_range 作文字对照；区分完全一致、空白/NFC 规范化一致、不一致和无法比较 | 不证明 OCR 正确、引用相关或语义支持；无法建立一一映射时保留未知 |

结果用 error / warning / unknown / info 分开显示。每类异常保留完整计数，最多展示 8 个位置，位置可打开相应文档的切片或解析块列表；列表不会自动筛选至单个位置，可用编号与来源块标识核对。没有综合分数，也没有“合格率”。

## 读取预算与指纹

每次最多 5,000 个块、2,000 个切片，按 ordinal 顺序读取；投影数据序列化累计最多 4,000,000 字节。正文单行最多读取 100,000 个字符，来源 JSON 单行超过 64,000 字节时不读该字段。数据库流式读取，不加载 embedding。

返回 `scope.total` / `scope.inspected`、`scope.complete`、`scope.content_complete`、`scope.sources_complete` 和 `scope.source_texts_complete`。达到预算则明确标为部分检查；块未读全时不能断言悬空来源，切片未读全或来源字段未读入时不计算页覆盖和未引用块。被截断的正文不参与 token 重算或精确重复判断。token 的 observed / unknown 仅以已读取切片为分母，未读取的数量由 scope 单列。记录数量读全不等于来源正文比对完整。

文字对照只追加读取有字符映射的被引用块，正文前缀上限 100,000 字符，仍计入同一字节预算。另有每文档 4,000,000 个来源加节选字符的比对预算，重复来源也计费；预算不足的来源项保留 `comparison_budget_exhausted`，不是一致。此限制是比对工作量上限，不是硬墙钟超时。

`snapshot_sha256` 标识本次已读取的文档元数据和投影数据，不是原文件完整性证明，也不是全库快照。规则版本另列 `schema_version`。诊断结束再检查文档更新时间：若期间正常重建改变了文档，返回 409，要求重试；响应禁止缓存。

## 当前边界与后续

本版不推断阅读顺序是否正确、不核验表格是否丢列、不验证图片内容、跨页语义或公式结果。失败/处理中可能保留旧索引，会明确提示；没有索引时显示未知。诊断结果尚未持久保存到批任务，也不会自动触发坏页重试。下一步先在固定的困难文档控制集中验证异常检出与误报，再接入批次摘要和有次数/成本限制的恢复，避免仅凭启发式反复重跑模型。

本版软件自验与页面证据见 验收记录（本地研究记录，未随公开包分发）。工程检查不能代替 M1 外审、M2 独立语义标注或真实问答质量评测。

## 批量诊断（2026-10-23 后续包）

在“查看批任务”中点击“检查整批来源与切片”，一次检查这一批的已有索引。接口为 `GET /api/v1/ingestion-batches/{id}/diagnostics`，仍为只读，不运行模型或触发恢复。单文件入口继续可用。批次没有关联文档的拒收项标不适用，文档已删除标来源不可用，正在处理的文档标暂未检查；失败文件也能展示已有索引或无索引的诊断。

每个输入保留一行；相同 document_id 在本次请求内只检查一次、复用结果。返回 `items` 和按 document_id 存放的唯一 `documents` 详情；`n_inputs` 与 `n_unique_inspected_documents` 分开，异常文档数按唯一文档计，输入状态计数之和必须等于输入数。inspected 只是检查返回，包含部分检查和没有索引的文件，不表示质量通过。

本批最多 20 个输入，历史异常大批次直接 422，不静默漏行；全部文档共用 8,000,000 字节投影读取预算，单文档仍遵循上述限制。每开始一个新文档前检查累计耗时是否已达 10 秒，这是**停止接纳下一份检查的预算，不是硬墙钟超时**；已经开始的有限文档会执行完。未检查行保留 deferred 及原因。索引在检查中变化时计入已消费字节，不能通过失败绕过预算。

结束时复查批作业事实和已检查文档更新时间，变化则显示 `changed_during_inspection`，对应详情可标 `stale`。这些结果是逐文档读取的观测，不是数据库原子快照。服务端不保存独立诊断历史；“导出本次诊断”下载 UTF-8 JSON，方便保存对照。读取中文 JSON 应显式使用 UTF-8，不依赖 PowerShell 5.1 的默认编码。

固定 [合成控制](../evaluation/diagnostics_v1/README.md) 经原生解析与真实结构分块，再注入明确机械故障验证告警边界；没有把合成检测成绩当自然脏文档准确率。历史 v1 未验证来源正文与切片节选，等长无关替换是其已知盲区。批量包的原始命令、页面与历史证据见 批量诊断交付（本地研究记录，未随公开包分发），这些旧结果不被本轮覆盖。

## 文字对照与审核修订（2026-10-24）

当前接口为 `persisted-integrity-v3`，文字契约为 `source-consistency-v2`。不提供 block_texts 的旧离线调用继续为 persisted-integrity-v1，显示 not_run；继任实现的 v2 与其原始结果保留为历史。

- 完全一致、空白折叠/NFC 后一致分别计数。二者不等于语义等价。
- 明确等长区间中的不同文字计不一致；表格/图注等布局敏感块提示需核对，不自动改索引。
- 既有分块器可能把同一块的来源按页裁剪，chunk_range 却仍覆盖整个片段。范围长度不同且规范化后不一致时，返回 ambiguous_character_mapping，不能据此断言文字损坏。其代价是没有明确映射的变长真错误也只能保留未知。
- 无来源对象的切片单独计 chunks_without_span_objects，不伪造来源项凑分母。可比对来源项为零时 status=unknown；部分项可比对时仍披露全部未知计数与范围。
- 每类最多展示 3 个文字对照样例、每侧最多 600 字符；不一致样例围绕首个实际差异截取，而非固定截正文开头。差异位置按 Unicode 码点计，导出附零基偏移与展示区间。

修订前后可复现反例、自动检查及真实侧边栏验收见 继任工作审核（本地研究记录，未随公开包分发）。软件控制集不能代替自然困难文档与独立语义评测；本次未运行付费模型或 M2 基线。

## 新切片的来源偏移修订

`structure-tokens-v2` 增加 `source_mapping_revision=piece-relative-ranges-v1`：当片段文字在来源块中精确且唯一定位时，将来源范围与片段交集转换成切片内相对区间，再叠加正文拼接偏移。来源区间不再一概指向整段正文；中文/Unicode 按码点定位，重叠片段各自换算。范围之外的正文仍保留，不伪造来源；表格或无法唯一定位的来源不补猜字符区间。

这可以改善自动诊断的可比性，以及局部引文筛选原页的精度；不改变正文、章节或切分预算，不解释图片或隐含关系。已有旧索引仍按旧记录诊断，不被后台自动改写。正常新摄入与新分块使用新规则；当前“重新分块”接口仍沿用原嵌入流程，本轮没有增加生产环境的“免向量重算迁移”接口。

[固定自然/布局控制对照](../evaluation/natural_diagnostics_v1/README.md) 可在无数据库、无模型的情况下复算，并拒绝对正文有变化的输出宣称“只改来源”。本轮验收副本复用原向量，原始索引保留；这与重新上传、重新 OCR 或问答质量基线是不同执行路径。

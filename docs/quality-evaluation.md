# 检索、回答与图谱质量验证

## 图谱构建的作用及边界

文档先解析为原始块和检索切片。构建图谱再从这些切片抽取实体名称、关系方向、谓词、描述、原文引文和限定信息，保存为实体节点与关系边。图谱检索通过问题中匹配的实体寻找关联原文，最多扩展两跳；图谱 + 文本将这些候选与向量、关键词候选融合。问答使用原始证据，不把路径本身当成已证明的推理结论。

例如 `API Gateway → 路由到 → Mercury worker → 存储于 → PostgreSQL` 可以帮助找到分散在 gateway.md 和 storage.md 的两段证据。图谱不保证每题提高效果，因此必须与同一题集的基础检索比较，记录改善、退化和不变的题目。

页面 **图谱与证据** 展示实际节点数量、关系方向、来源文档、原文和完整来源切片，可按实体或关系筛选并翻页。检查引文与名称存在，只能排除一部分编造，不能证明关系语义正确。

`qualified-relations-v2` 为关系保存 environment/version/condition/negation/modality/time 等限定的原文引文。引文不在对应切片的关系会被排除；出现已识别的显式条件信号却未报告限定时，也会被排除。相同端点、谓词在不同限定下保留为不同事实，避免去重吞掉相反规则。旧关系没有结构化限定时显示未知，需要重建图谱才能补充。有限的条件信号规则不能证明所有隐含条件都已覆盖。

实体目前主要按名称规范化合并，尚无完整类型消歧与别名判定。PDF 图片箭头理解、通用跨页关系推断、版本优先级和计算引擎仍待研发。

## 页面使用

1. 进入知识库，点 **质量验证**，选择配套固定题集，或选 **自定义题集** 上传题集 JSON。
2. 设置 top-k；图谱已构建时可勾选图谱 + 文本对照。未建图的对照会显示不可用，不会把空图表现当成图谱效果。
3. 按需开启模型评审。它额外检查答案依据、标准要点和抽样图谱关系；默认复用聊天模型，页面明确提示同模型自评偏差。
4. 可选择同一知识库过去的质量报告作历史回归基线。题集、语料快照或 top-k 改变时不能直接比较。
5. 报告逐题显示标准原文、基础召回排名、展开候选位置、进入上下文的位置、最终引用位置及遗漏阶段；可展开实际回答与模型评审。

完整来源匹配基于已标注的文件名和原文片段，支持一个切片覆盖多个必要证据。题集应由人抽样核对原文件及标准答案，不能让生成模型同时产生答案、自动认定标准、再自评为正确。

## 指标含义

| 指标 | 验证什么 | 局限 |
|---|---|---|
| Recall@k | 标注的必要证据找回了多少 | 金标不全或引文边界不当会影响分数 |
| Precision@k | 前 k 个位置有多少匹配标准证据 | 未标注相关片段可能被漏算 |
| MRR | 第一条相关结果排得是否靠前 | 不能证明多跳证据齐全 |
| nDCG@k | 与金标匹配的切片排序质量 | 当前为二元相关性，标准集合由固定引文匹配当前索引生成 |
| 完整证据率 | 所有必要证据是否同时找回、进入上下文或被引用 | 需区分候选池、实际上下文和引文三个阶段 |
| 拒答判断符合标注 | 有答案/无答案题是否按预期回答或拒答 | 评审服务不可用造成的拒答不计作通过 |
| 答案支持度估算 | 答案陈述是否由实际给模型的上下文支持 | LLM 评审有误差；忠于上下文仍可能答不全 |
| 要点覆盖估算 | 标准答案的必要事实在回答中覆盖多少 | 不等于通用正确率，也不能验证现实世界真实性 |
| 中英/同义一致性 | 同组问题是否取得相同标准证据 | 两种问法都失败也可能一致，因此另列全部证据齐全状态 |
| 关系支持度估算 | 抽样关系的方向、条件、谓词是否受来源支持 | 模型判断，最多检查前 40 条，不是图谱总体准确率 |

IR 指标可参照 [ir-measures](https://ir-measur.es/en/latest/measures.html)；答案依据评审思路参照 [Ragas Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)。本项目实现独立的来源追踪及模型结果校验，未将 Ragas 库作为运行依赖。

模型评审逐单元检查实际回答，声称“有依据”必须提供存在于实际上下文的引文，声称“覆盖要点”必须提供实际回答中的引文。遗漏、重复、格式错误、超预算和服务失败记为未知；未知不会当成满分。报告展示每个平均指标的有效样本数，不能把不同分母的模型估算直接当成严格优劣。

规则检查也有边界：固定金标原文在解析块中未匹配，只标“解析或标注不匹配”，不直接断言解析器出错；切片边界变化也可能影响字面匹配。答案审核单元切分不是完整的逻辑原子化证明。

## 题集与命令行

`evaluation/quality-template.json` 提供自定义格式。至少包含 version、source 和 cases，每题需要唯一 id、question、reference_answer、should_refuse、relevant_evidence。必要时用 required_facts 明确多个要点；同义/中英题用 equivalence_group 归组。不要把一段完整参考回答的所有措辞都机械视为必须逐字出现的事实。

```powershell
docker compose exec -T api python -m knowflow.app.evaluate_quality --knowledge-base-id YOUR_KB_ID --dataset /app/evaluation/dataset.json --strategies hybrid graph_hybrid --top-k 3 --judge
```

命令行可指定 `--baseline PATH`；固定标注的证据覆盖、MRR/nDCG 排序或拒答指标退化、基线不可比较时返回非零退出码。`--strict --judge` 还会拒绝将未完成的模型评审视为全部通过。输出以 UUID 为文件名保存，可在页面知识库的实验记录中查看。

独立评审模型可通过 `EVAL_JUDGE_API_KEY`、`EVAL_JUDGE_BASE_URL`、`EVAL_JUDGE_MODEL` 配置；不用修改聊天或 embedding 配置。不配置时复用聊天模型，不能声称评审独立。

## 工程状态

每题完成后保存结果，另有评测心跳。API 进程重启后的原任务显示中断；外部命令行任务依赖心跳判断是否失联。未实现崩溃自动续作和分布式持久队列。评测期间语料、切片或图谱快照改变时标为不可直接对照。

图谱改造前首次受控运行共 11 题 × 2 策略，10 题可回答、1 题无答案；基础混合检索标准证据 Recall@3=0.9、上下文完整证据率=0.8；图谱 + 文本分别为 1.0、1.0，两道中英多跳题补齐了证据。模型评审标记出一条可能丢失 staging/may 限定的关系，促成结构化限定改造。完整原始报告保留在运行目录，压缩归档 `evaluation/baselines/quality-graph-before-scope-20261022.json`。

这份受控结果不能外推为生产准确率，也不能证明图谱总是优于基础检索。限定改造后的复查结果另行记录，保留之前的失败与未知项。

限定改造后独立执行的 `answer-review-v2` 复查共 16 条关系，模型给出 15 条支持、1 条缺乏支持（谓词与目标对象不匹配），分批评审完成；这一同模型估算不是 93.75% 的真实图谱准确率。旧版评审曾错误借用另一切片的引文，被来源约束重新校验为未知，旧报告已保留。新复查归档 `evaluation/baselines/graph-scoped-audit-v2-20261022.json`。该次离线评审只报告问题，保留原结果；后续自动语义门禁见下文。

## 自动关系语义门禁（后续开发）

构建图谱在抽取、原文与限定校验后，自动分批检查全部候选关系（每批 4 条，并发 2；没有离线抽样的 40 条上限）。只有模型判 supported 且自己的来源引文通过校验的关系参与图遍历。unsupported/contradicted/unknown/unreviewed 仍保存，但不参与图扩展，也不能经实体提及候选绕过过滤。文本与向量检索继续检索原文；这不等于删除源信息。

图谱页面可按可检索、缺乏依据/矛盾、未知、旧索引未审核筛选，并展示原因。文档状态显示可检索关系数；旧图谱需重建才能参与新门禁下的图检索，没有静默标成通过。评审服务故障时，候选标未知，不能把空可用图用于证明图谱无效。

审核缓存包含来源切片身份和内容、关系及限定、评审提示词、模型与服务地址指纹。相同已完成的支持/排除判定可以复用；未知会重试。每次仍抽取候选，只有完全相同的候选可复用审核。缓存没有跨文件或跨用户共享。审核增加 LLM 调用与耗时；超时按 EVAL_JUDGE_TIMEOUT_SECONDS 处理。

这是一道模型辅助质量过滤，可能误收或误排。尚不能据此声称所有可用关系真实正确，仍需独立金标和错误样本回归。

为结构化抽取和审核使用 MiMo 官方接口时，默认 STRUCTURED_MIMO_THINKING=disabled，并设置整次请求的绝对时限。普通回答仍保持原来的模型设置；其他模型/接口不会收到 MiMo 参数。可设 enabled 或 provider_default 恢复，模式改变会使关系审核缓存失效。该选择按 [MiMo 官方 OpenAI 兼容参数](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api) 实现；速度和判定质量需要用同一旧候选重放比较，不能只凭耗时选择。

## 文本候选保留与图谱补充

`text-preserving-graph-union-v1` 取消文本、图谱三通道加分后共同截断的做法。`graph_hybrid` 先取得与 `hybrid` 相同的文本前 k 条（含原有表格行通道），保留次序和分数，再去重补入最多 k 条图谱候选。同一来源只出现一次，共同命中会保留 graph_rank；图谱候选仍只来自已通过语义门禁的关系。

这是候选可用性的保护，不保证相关性模型一定接受、预算一定容纳或回答正确。图谱补充最多使文内引用展开前的候选变为 2k；引用展开仍有独立上限，相关性与生成 token 预算没有扩大。可能增加审核耗时；不能把扩展后收益当作相同候选数量的消融结果，也不能宣称只有图谱才可获得该收益。严格对照还需相同额外预算的文本候选扩展。

响应的 `graph_expansion` 记录策略版本、基础/共享/新增候选数和上限，逐片 `retrieval_stage` 区分基础召回、图谱补充和文内引用补充。离线轨迹的 base 只包含文本基础前 k 条；基础 Recall@k、MRR、Precision/nDCG 不含新增图谱证据，candidates/context 指标分别报告扩展收益和后续损失。页面展示新增预算、候选来源和每题候选策略。旧报告没有这些字段时不补造数据。

“拒答标志符合标注”仍是结构化 refused 标志的检查，不能代替回答是否在语义上拒答的判断。原始回答和独立要点审核继续保留，不能把回答说“无法判断”却标志为 false 当作正确回答。

现场自由改写失败后进一步改为 `text-seeded-graph-union-v2`：除问题里的字面实体名外，还从文本前 3 条命中来源的实体提及起步。这些提及必须在同一来源中有已审核关系支持，始终受知识库、文档就绪状态与关系门禁约束；不会根据名称包含关系把短名、worker、production service 当作同一实体。实体种子最多 20 个，图遍历最多两跳，最后去重补充最多 k 条新候选。

使用文本来源作为种子时，不再要求每份图谱相邻来源重复问题的字面词语，否则中文问英文资料仍会被全文匹配过滤。关键词分数保留为排序提示，不充当这条补充路径的硬门槛。纯图谱检索的字面起步行为仍保留。候选补全不代表这些关系足以支持问题，后续相关性检查和引文验证继续执行。全局向量距离阈值未放宽，也未使用按题目、实体名或文件名返回答案的分支。此前 v1 的预算对照与整套回归结果不能当成 v2 的泛化验收。

`text-seeded-graph-union-v3-empty-recovery` 处理常规混合候选全部为空的情况：仅在相关性检查开启时，对完整问题及拆分查询进行有上限的最近邻恢复，每个查询最多 1 条、去重后仍不超过文本 k。该路径使用单次请求的距离筛选副本取得候选，全局配置的 0.35 阈值没有改动；恢复候选可能超过阈值，必须明确标记 `distance_gate_fallback` 并通过后续逐片相关性核验。相关性检查关闭时禁止恢复；模型核验未知或不可用时仍不采用。它不保证语料里一定有答案，不能把“有候选”解释成“有依据”。恢复的文本来源也可以为有门禁、受预算限制的图谱补充提供种子。

## 按任务选择模型与思考模式

主模型与复杂模型共享 LLM_API_KEY / LLM_BASE_URL，分别由 LLM_MODEL 与 LLM_COMPLEX_MODEL 指定。当前本地配置为 Qwen3.8-Flash / Qwen3.8-Max。单来源简单问答采用 LLM_SIMPLE_THINKING；命中否定、环境、版本、条件、长内容规则的相关性判断，以及多来源回答，采用 LLM_COMPLEX_THINKING。图谱关系抽取统一采用复杂模型及复杂思考模式，短句同样需要语义角色判断；不会按某个题目或实体名特判。推理强度通过 LLM_REASONING_EFFORT 配置，初始为 low。规则可能漏判或误判复杂度，不是已训练的智能路由模型；复杂模型增加离线建图成本，仍需评测。

独立审核使用 EVAL_JUDGE_* 与 EVAL_JUDGE_THINKING，当前为 deepseek-flash、思考开启。完整版本名 DeepSeek-V4.1-Flash-1017 与 API 调用 ID deepseek-flash 不相同；按 [DeepSeek 官方模型目录](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 使用调用 ID，不能把展示名称直接替换为接口参数。别名可能随供应商更新，报告保留调用 ID、日期与选模规则；尚不能保证固定到不可变模型权重。

抽取报告记录每个批次的模型与思考模式；相关性诊断记录审核模型；回答头部展示所请求的生成模型与思考模式。离线质量报告保存实际响应中的路由配置。思考过程不会展示给用户。Qwen 的格式修复重试按协议回传必要的 reasoning_content，避免混合思考模型多轮上下文缺失。

结构化参数只发送到明确支持的官方接口，不把千问 enable_thinking 发送给 DeepSeek，也不把 DeepSeek thinking 参数发送给其他服务。仍保留绝对时限与未知状态，模型切换不绕过引文或关系语义门禁。

## 环境、版本与未知项的生成回归

页面验收发现过正文正确、表格却把 production 的超时复制到 staging 的错误。生成提示现在要求逐个表格单元格检查主体、环境、版本和条件，缺失值明确写未知；来源只禁止某类操作时，不能推出其他操作被允许，也不能断言不存在更广的禁令。这是提示约束，不能保证完全消除幻觉。

`evaluation/scoped_answer_cases.json` 固定三类合成用例：跨环境表格缺失值、worker 与 production service 的身份混同，以及请求正文禁写与所有写入禁令的区别。使用当前生成路由和独立审核重放：

```powershell
.\.venv\Scripts\python.exe evaluation/evaluate_answer_scope.py `
  --output evaluation/results/answer-scope-local.json
```

它直接给生成模型提供固定原文，单独验证生成层，不测召回；报告记录题集、提示及来源摘要、答案、实际请求路由和逐项审核。保留未知、失败和首次运行，不能靠反复重跑挑选一次通过的结果。整条检索链仍需使用上文的质量验证。

## 普适机制与迁移保留集

修复依据是错误机制，不能按题目 ID、公司名、文档名或特定年份返回特制答案。当前排除句处理仅识别独立的显式排除表达，不能声称覆盖所有语言中的否定；完整问题仍传给相关性判断和生成。图谱谓词要求保留连接目标所必需的语义角色和介词，不能用关系描述掩盖错误三元组。这些通用约束是否有效仍需外部数据验证。

开发回归集和验收保留集分离。`evaluation/holdout_v1/` 保存跨领域合成迁移用例、验收协议和首次运行前的实现/题集/语料 SHA256。该集由同一开发者构造，不是真实独立人工盲测。首次输出中的失败保留，不针对该输出继续调参后冒充首次成绩。真实普适性需要额外的独立标注资料，按文档、组织、时间及格式隔离，并报告每组分母、失败和未知。

`evaluation/evaluate_metamorphic.py --output evaluation/results/metamorphic-local.json --strict` 用同一问题检查来源反序、无关数据加入、关键来源删除。只测生成层；不能用它替代整条检索链及实际 PDF 的稳定性测试。

指标版本 `gold-evidence-v2-citation-sources` 新增 `citation_sources_evidence_recall` / `citation_sources_complete_evidence`。它要求金标确实已进入模型上下文，引用的 chunk/文件身份匹配且非空节选存在于同一上下文。它只说明金标所在来源被实际引用，不证明引用节选支持答案。原来的 `citations_*` 仍要求全文匹配金标，不改变历史口径。二者分别展示，旧报告无新指标时为未知。只有相同指标版本才比较新增指标，已有排名、召回和全文匹配回归继续保留。

随后自查发现 v2 对 API 使用 `换行＋…＋换行` 拼接的多段节选漏算。`gold-evidence-v3-citation-excerpts` 校验每一段非空节选均存在于同一上下文，不接受任意省略号或伪造片段。`evaluation/replay_quality_metrics.py --input <原报告> --dataset <原题集>` 在索引身份未改变时重放已保存的轨迹，创建单独报告并记录原运行 ID；不重做问答、不覆盖原报告、不更换模型审核结果。该测量修正与后续抽取模型路由迭代分别记录，不能混成同一版保留集成绩。
